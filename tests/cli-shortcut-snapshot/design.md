# CLI Shortcut Snapshot Design

## Why This Exists

Tier A (`verify-change`'s `expected-bins.txt` check) confirms a CLI binary
is present after building, but says nothing about whether its _configuration_
actually works.
For interactive CLIs like herdr, the question is: does
pressing the configured shortcut key actually fire the bound action?

This suite answers that question using VHS tape files, in two modes:

- **`--check`** (automated, replaces the former pytest-based Tier B):
  runs the tape, captures the last rendered text frame, and asserts
  structural markers from a `.assertions` sidecar file.
- **default** (visual): records a `.webm` video for human review.

## Why the Remote Approach Does Not Work

Driving an already-running herdr session remotely (`herdr pane send-keys`,
`herdr terminal attach <existing-terminal-id>`) never reaches herdr's
keybinding router — it injects raw bytes straight into the pane's PTY, or
(for `terminal attach`) renders correctly but still doesn't route keys,
because the connection isn't recognized as a genuine interactive client.
Verified empirically with herdr's own built-in `prefix+z` (zoom) binding
on a freshly created scratch pane.

## Why This Works

`herdr --session <name>` launches herdr itself as the foreground process
reading raw stdin — the same code path a human sitting at a real terminal
exercises, not herdr's separate remote-control socket API.
Verified empirically:

- `ctrl+b` rendered herdr's own `PREFIX` indicator banner (proof the
  keybinding router engaged).
- `ctrl+b` then `z` set `zoomed: true` in `herdr pane layout`'s output.
- `modules/herdr/config.toml`'s actual `prefix+ctrl+r` ->
  `persiyanov.reviewr.toggle` binding opened the reviewr panel.

### The Nested-herdr Guard

Running `herdr --session <name>` from inside another herdr-managed pane
fails with `nested herdr is disabled by default`.
`scripts/run.sh` strips `HERDR_ENV`/`HERDR_PANE_ID`/`HERDR_WORKSPACE_ID`/
`HERDR_TAB_ID` from the environment before invoking VHS — enough to pass
the guard while still launching a completely isolated, disposable named
session unrelated to the caller's real one.

## Why VHS

VHS was initially rejected because it drives whatever shell/command it
spawns through the same raw-pty-byte-injection mechanism that doesn't work
for herdr's _remote_ control path.
Once the target shifted from "drive an existing session remotely" to
"launch the CLI as its own foreground process," that objection no longer
applies — VHS's actual purpose (record a real interactive terminal session
driven by literal typed input) is exactly this suite's use case.

Dependencies (`vhs`, `ttyd`, `ffmpeg`) are all plain prebuilt nixpkgs
packages; `pkgs.vhs` pulls in `ttyd`/`ffmpeg` automatically.
The `cli-shortcut-snapshot` devShell in `flake.nix` only needs to list `vhs`.

## Structural Assertions (--check mode)

Golden-file comparison was investigated and rejected: the reviewr panel
displays the current git diff, which changes on every commit.
Normalizing enough of the diff content to produce a stable golden file
required filters complex enough to defeat the purpose.

Instead, `--check` uses structural assertions — a `.assertions` sidecar
file next to each tape, containing one extended-regex pattern per line.
The test passes when every pattern appears somewhere in the last rendered
text frame.
This checks what we actually care about (did the panel
open? did the sidebar render? is the header present?) without being
coupled to the diff content.

The `.txt` output is generated by injecting an `Output <file>.txt`
directive into a temporary copy of the tape.
VHS's `.txt` output concatenates all rendered frames separated by `─`
lines; `scripts/extract-last-frame.sh` extracts just the last one.

## Why pytest Was Removed

The former Tier B (`tests/cli-config-behavior/test_herdr_shortcuts.py`)
used Python's `pty`/`subprocess` to launch `herdr --session <name>`,
drain the PTY in a background thread, send `ctrl+b`/`ctrl+r` as raw
bytes, and assert on `herdr --session <name> pane list` JSON (pane count
increase).
This worked but required a Python devShell with pytest/pytest-html, a
dedicated skill, its own run.sh, and ~110 lines of non-trivial PTY
management code.
VHS's `.tape` DSL does exactly the same thing (launch herdr, type keys,
wait) in 12 lines, and the structural assertion replaces the JSON-API
pane-count check with a text-frame pattern match that also catches visual
regressions pytest could not (panel border missing, sidebar not rendered,
header text changed).
The Python test's PTY drain thread is no longer needed because VHS manages
its own terminal lifecycle.

## Publishing (.webm mode)

Same pattern as `tests/e2e-navidrome/scripts/run.sh`: copies `.webm` +
`player.html` into `modules/static-reports`'s
`dataDir/<branch-slug>/cli-shortcut-snapshot/<tape-name>/`, prunes entries
older than 14 days, `trap cleanup EXIT`.

## CI

Manual-only, invoked via the `cli-shortcut-snapshot` skill — not wired
into CI.
